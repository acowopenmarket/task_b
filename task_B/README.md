# task_B：全画面 RGB-D 定位与夹取

本机按钮操作：双击 `启动操作面板.cmd`，在浏览器使用“回观察位”和“开始 task_B”，详情见 CONTROL_PANEL_GUIDE.md。启动页面不会执行动作。

当前识别链：相邻深度连续表面提案（保留重叠深度带作为补充）→ 彩色 GrabCut 分割 → 区域重合度检查 → 目标区域深度中位数 → 手眼坐标转换 → 夹取 → 新拍复查。

抓取后返回观察位，满足任一条件即成功并松爪：连续复查确认原目标源区域已清空（ABSENT），或一次有效的多帧识别确认目标（PRESENT）且物体区域有效深度中位数 `rgbd_candidate.depth_m < 0.171` 米。近距离条件不再要求连续两轮复查，单轮内部仍保留多帧深度稳定性和同步校验。这里的距离为相机光轴方向深度，171 mm 本身不满足“小于”。UNKNOWN 和无效深度不算成功。结果记录 `success_reason`、`target_camera_depth_m`、`success_depth_threshold_m` 和复查采集 ID。此新判据已加入离线测试，尚未实机验证。

2026-10-28 已修复曲面物体被固定深度带拆分而定位失败的问题；12 组当日真实记录离线回放及完整离线回归通过。当前修复未执行实机动作，证据见 runs/curved_fix_20261028/REPORT.md。

不拟合桌面、不识别箱体、不限制颜色、不裁剪固定 ROI，不要求整幅画面深度完整。候选点 Z 来自物体自身有效深度，不是桌面高度或体积中心。深度提案与彩色结果是相关的，重合度属于一致性检查，不代表两个独立识别器都确认了物体身份。

保留目标深度的有效性、多帧稳定和 RGB-D 对应检查，以及原机器人到位、同步标定、夹爪偏移、44毫米插入规则、法兰 Z 下限。已移除全画面可见障碍高度对定位/目标生成的阻断；现有运动程序不提供完整碰撞规划。

只读采集：`bash run_task_b.sh --capture`。实机执行：`bash run_task_b.sh --execute`。执行前仍使用现场真实配置；保存数据只能离线回放，不直接执行历史坐标。

只需识别物体及 IoU 时使用 `bash run_task_b.sh --vision-only`：仅启动相机，输出光学相机坐标与 rgb_depth_iou，不启动机器人 bridge、不订阅机器人反馈、不连接夹爪，机械臂可以保持关闭。完整定位/抓取模式仍保留原机器人状态与同步校验。RGB-D 配对会在缓冲中选择最新的完整新鲜帧组，避免只检查最新彩色帧而遗漏稍晚到达的深度或内参；不放宽同步时间上限。

离线定位测试：`python -m unittest -v test_rgbd_candidate`（需 numpy、OpenCV）。完整回归：`python verify_offline.py`，需要同级 camera、estun、jia 等原项目。
